## Local results in detail

Services: Docker containers `greenscape-postgres-1`, `greenscape-mongo-1`, `greenscape-redis-1` and the local
Supabase, all on this machine. No hosted database or account was used.

**Migrations.** `pnpm db:deploy` against the local Postgres: "13 migrations found in prisma/migrations … No pending
migrations to apply." The integration adds no migration.

**Lint.** One warning, not new: `apps/web/components/account/account-client.tsx:146:5` (`window.location.assign`).

**Integration tests.** First run: 20 files passed, 1 failed; 189 tests passed, 1 failed; 316.62 s. The failure:

```
tests/integration/auth.test.ts > rejects a correctly signed token once it has expired
ENOENT: no such file or directory, open '…/supabase/signing_keys.json'
```

That file is gitignored and made per machine; a fresh worktree does not have it. It was copied from the main
checkout and `auth.test.ts` rerun: 12 of 12 passed (23.06 s). The whole suite was not rerun locally afterwards; on
GitHub, where the key is generated by the stack setup, all 190 pass.

**Playwright, full suite.** `pnpm test:e2e`, 07:43 to 08:55, 344 tests, 4 workers, exit 1:

```
  82 failed
  60 skipped
  4 did not run
  198 passed (1.2h)
```

This run does not say what it appears to say. Ports 3000 to 3002 and 4000 were already held by servers this
integration did not start (`next dev` from the main checkout, an API from another session's worktree), and they
were not stopped because they were not this session's to stop. Playwright reuses running servers outside CI, so the
suite ran against dev servers, not a production build. Then, at 07:52:51, nine minutes into the run, those dev
servers were restarted (the main checkout had just pulled the merged `main`). Error lines in the log by kind: 31 "Test timeout
of … exceeded" (90 s to 600 s), 18 `toBeVisible`, 16 `toHaveURL` (for example a sign-in that lands back on
`/auth/login`), a handful of others. The failures are spread over 31 spec-and-project pairs, including specs the
integration cannot have affected: nothing under `apps/`, `packages/` or `docker/` differs from `main` before the
merge.

What was tried to confirm that: a rerun of only the 82 failed tests. It did not happen. The smoke run (a different
Playwright config) overwrote `test-results/.last-run.json`, so `--last-failed` found nothing; and by the time that
was noticed (16:45, after a pause in this session) the dev servers on 3000 and 3001 no longer answered at all
(`/api/health`: no reply in 90 s). So the local failures are **explained, not disproved**. The evidence that they
are not real is GitHub's two full runs of the same tree with 0 failed.
